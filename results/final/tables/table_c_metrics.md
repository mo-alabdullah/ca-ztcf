# Table C — metric definitions

> **FINAL THESIS EXPERIMENTAL EVIDENCE. Tier-2 live software-based testbed: real 5G NAS/NGAP/GTP-U via Open5GS and UERANSIM, and a real IEEE 802.11 association and EAP-TLS exchange via mac80211_hwsim, over simulated radios. Not an RF, propagation, interference, channel-quality, spectrum-coexistence or physical-handover measurement. Generated from results/final/raw/; no value was typed by hand.**
>
> Generated by `scripts/process_final_results.py`. Descriptive statistics
> only in this file; tests and effect sizes are in Table K.

What each metric measures, and the subject each run recorded for it. The subject matters: a decision latency and an access-context latency are not comparable, and neither is a measurement of a radio.

**Timing quantities are distinct and are never conflated:** access authentication latency, path-switch latency, trust decision latency, application recovery latency and end-to-end transition duration. In the transition records, `T4 → T5` includes agent process start-up and is **not** pure decision latency; the decision alone is `trust_decision_ms`.

| Id | Name | Unit | Subject observed | Definition |
|---|---|---|---|---|
| M1 | authentication_latency | ms | - | Authentication latency. At the application this is CONNECT to CONNACK; on the WLAN path it is the EAP-TLS exchange. The subject is recorded per sample so the two are never conflated. |
| M2 | transition_duration | ms | - | Access-context switch initiated to the first decision under the new context. Orchestration time; NOT an 802.11 handover latency. |
| M3 | decision_latency | ms | - | Decision request issued to decision returned, measured at the caller. |
| M4 | application_transition_completion | ms | - | Transition initiated to the device regaining its full access scope. |
| M5 | reauthentication_count | count | - | Number of REAUTHENTICATE actions issued. |
| M6 | step_up_count | count | - | Number of STEP_UP_AUTHENTICATION actions issued. |
| M7 | trust_state_transitions | count | - | Count of trust-state changes, by (from, to) pair. |
| M8 | messages_exchanged | count | - | MQTT control packets exchanged between device and enforcement point. |
| M9 | bytes_exchanged | bytes | - | Bytes on the device-to-enforcement-point socket, by direction. |
| M10 | ca_ztcf_cpu | percent | - | CPU utilisation of the measured subject: a container where a container deployment is measured, otherwise the experiment process, as CPU seconds over wall time. NEVER an IoT device. Each run records which subject it measured. |
| M11 | ca_ztcf_memory | MiB | - | Resident memory of the measured subject: a container where a container deployment is measured, otherwise the experiment process's peak resident set. NEVER an IoT device. Each run records which subject it measured. |
| M12 | engine_evaluation_time | us | - | Pure predicate evaluation and state derivation, excluding transport. |
| M13 | successful_legitimate_transitions | count | - | Transitions labelled legitimate that completed without denial or quarantine. |
| M14 | denied_restricted_transitions | count | - | Transitions that received DENY, QUARANTINE or a blocking step-up. |
| M15 | false_acceptance_raw | count | - | Steps labelled illegitimate that were allowed. Raw count, always reported with its denominator. |
| M16 | false_rejection_raw | count | - | Steps labelled legitimate that were denied or quarantined. Raw count, always reported with its denominator. |
| M17 | correct_decisions_raw | count | - | Correct acceptances and correct rejections, as raw counts. |
| M18 | policy_action_distribution | count | - | Count of decisions per policy action. |
| M19 | mqtt_operation_outcomes | count | - | MQTT publishes and subscriptions, split by permitted and refused. |
| M20 | run_metadata | n/a | - | Device count, seed, durations and environment metadata for the run. |
| M1_EAP | eap_authentication_latency | ms | - | Time to obtain the WLAN access context. On Tier 1 this is an 802.1X/EAP-TLS authentication-path exchange over a wired driver; on Tier 2 it is an observation read from hostapd's own log of a real 802.11 association and EAP-TLS exchange over a simulated PHY. Each run records which. NOT a radio measurement in either case. |
| M1_NR | nr_context_latency | ms | - | Time to obtain the 5G access context. On Tier 1 this is a synthetic fixture and costs nothing to establish; on Tier 2 it is an observation read from a live Open5GS core. Each run records which. It is the cost of obtaining the context, NOT a radio measurement in either case. |
